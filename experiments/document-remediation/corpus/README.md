# Synthetic test corpus

12 documents authored as semantic HTML and rendered to PDF through Chromium.
Regenerate with `node ../make-images.mjs && node ../generate-corpus.mjs` from
the experiment directory.

## Why synthetic

We need ground truth. Grading a remediation tool against structure read back
out of that same tool's output measures nothing. Authoring the source means we
know the intended heading hierarchy, reading order, table header relationships,
and which graphics are decorative — before any tool touches the file.

## What the HTML is and is not

**[V]** Chromium's `page.pdf()` emits an untagged PDF: veraPDF reports 7.1-11
(no structure hierarchy), 6.2-1 (no MarkInfo) and 7.1-3 (content neither tagged
nor marked as artifact) against a probe document.

So the HTML semantics — `<h2>`, `<th scope>`, `<figcaption>` — **do not survive
into the PDF**. They are ground-truth documentation, not PDF structure. What
reaches the PDF is glyph positions, images, and vector paths. OpenDataLoader has
to re-derive everything from geometry, which is the real problem.

That means "adversarial" here means *visually* ambiguous, not
semantically sloppy in the markup.

## Known limitation — read this before trusting a PROCEED

A clean HTML generator produces easier PDFs than InDesign, Word, or a scanner.
Real client documents carry generator quirks this corpus does not reproduce.
**A PROCEED result from this corpus is an upper bound, not a prediction.**
Documents 02, 04, 06, 08, 09 and 12 are authored adversarially to push back
against that bias, but they cannot remove it.

## Ground truth

Every document has `<name>.ground-truth.json` recording intended title,
language, heading hierarchy, reading order, lists, tables and their header
relationships, figures, decorative graphics, expected alt-text sources, links,
artifacts, and every intentionally introduced problem.

Several sidecars carry an `expectedOutcome` field naming the result that would
be *wrong*. Document 06 should not reach DELIVERABLE by automation — if it does,
the pipeline is fabricating descriptions rather than remediating.

## Generation notes

- Images (`img/`) are generated by `make-images.mjs`, which hand-encodes PNGs
  via `zlib`. Byte-identical across runs.
- Document 09 is the exception to `page.pdf()`: rendered to PNG by Playwright
  screenshot, then reassembled with `pdfbox fromimage`. It is the only way to
  get a PDF with no text layer.
- Per-document `@page` rules are honoured via `preferCSSPageSize`, which is how
  08 gets a landscape MediaBox (841.92 × 594.96) while the rest are portrait.
- Output is *semantically* reproducible, not byte-identical: PDFs carry a
  `/CreationDate` and font subsetting can vary. Normalising that was considered
  and dropped — nothing in the experiment compares PDF bytes.
