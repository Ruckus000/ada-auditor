# Phase 2 — Multi-page audits, then the operator UI

Phase 1 shipped (7 commits, branch `claude/product-e2e-audit-62f635`): axe-core
engine, real targets with SSRF defence, real AI advisory, durable artifacts,
PDF export, async runs. 322 tests green.

## Decisions (locked)

| Decision | Choice | Consequence |
|---|---|---|
| Sequencing | **Multi-page scanning before the schema** | The record gains a page dimension before Postgres is designed around it |
| Database | **Neon Postgres via Vercel Marketplace** | One vendor ecosystem alongside Upstash + Blob; credentials injected by Vercel. No bundled auth. |
| Auth | **Keep the console token, add an operator name** | No auth vendor, no login flow. Activity is attributed to a configured operator. |
| Prototype | **Let real data reshape the screens** | Visual design is kept; panels with nothing real behind them change or go |

Two things follow from the auth decision that should not be quietly reversed
later: there is no per-user identity, so the prototype's People and Invite
screens have nothing to back them and are dropped rather than mocked; and there
is no RLS story, because there is one trusted operator group rather than
mutually distrustful tenants.

## 2A — Multi-page scanning (do this first)

### Why it comes first

A run scans exactly one page — the journey's last. Every page walked through is
discarded. Demonstrated:

| Journey | Verdict | Findings |
|---|---|---|
| Ends on `violations.html` | fail | 5 |
| **Passes through** `violations.html`, ends clean | **pass** | **0** |

A journey stepping through a page with five real WCAG violations reports a
clean pass. For a product describing itself as an auditor for *multi-step* apps
that is misleading in the same shape the regex was, and no screen fixes it
because the data is not there. Every comparable tool (Lighthouse, axe-cli,
pa11y) models results as per-URL aggregated into a run; our record has no page
field at all.

Doing this after the schema means a Postgres migration plus rewriting every
screen that reads findings.

### Shape

`runJourney` scans after **each navigation**, not once at the end:

```ts
export type PageAudit = {
  page: JourneyPageMeta;
  axe: AxeScanResult;
  axTree: AxNodeSummary[];
  artifacts: JourneyArtifacts;   // one set per page
};

export type JourneyRunnerResult = { pages: PageAudit[] };
```

Ripples, all of which are the point:

- **`DeterministicFinding` gains `pageUrl`.** A finding that cannot say which
  page it is on is not actionable in a multi-page run.
- **`findingKey` becomes `source:code:pageUrl:selector`** ([regression.ts:17](../../../src/services/regression.ts)).
  Without the page, the same rule on the same selector across two pages
  collapses into one entry — the same class of bug the selector fixed.
- **`evidenceStatus` is per page; the run takes the worst.** The steady-state
  rule holds unchanged: any page with incomplete evidence makes the run
  inconclusive and its deterministic findings are rejected.
- **Artifacts key per page**, `runs/<requestId>/<stepId>/…`. `stepId` currently
  names one artifact set; it becomes a per-page prefix. Keep
  `resolveArtifactPrefix`'s traversal check.
- **`summarizeRun` aggregates** across pages.
- **The advisory runs once over the aggregate**, not per page — N× cost for
  little gain, and cross-page issues (inconsistent nav, heading structure
  drifting between pages) only become visible in aggregate.

### Cost ceiling

N pages × (axe + full-page screenshot + AX tree) against the same 300s
`maxDuration`. Cap pages per run (start at 20, configurable) and **log when the
cap truncates** — a silent cap reads as "audited everything" when it did not.
If real journeys exceed the ceiling, that is the signal for the container
worker, not a bigger number.

### Verification

The probe above, inverted: a journey passing through `violations.html` must
report those five findings with `pageUrl` pointing at that page, and the clean
final page must not suppress them. Chaos stays green.

## 2B — Neon Postgres

Only after 2A, so the schema is designed around the real record shape.

**Provision** via `vercel integration` (Marketplace) so credentials are injected
rather than hand-managed.

**Tables:** `clients`, `journeys` (steps JSONB), `runs`, `run_pages`,
`findings` (with `status: open|fixed|dismissed`, `note`), `reports`
(`share_token`), `activity_events`, `client_config`.

**Not created:** `people`, `integrations`, `invites`. They serve Phase 3 and
have no backing decision — creating tables for unbuilt features is the YAGNI
violation `AGENTS.md` leads with.

**`RunStore` gains `list`.** Called out in the Phase 1 plan and never delivered
— the interface is still `saveRun` / `getRun` / `getLatestRun`, so there is no
way to enumerate history. It lands here with the store that can actually do it.

`FileRunStore` and `KvRunStore` are **replaced**, not joined. Their known
weaknesses die with them: O(n) full-directory reads per call, a two-deep KV
pointer chain, and the double `getLatestRun` on every `runs/latest` request.

## 2C — Screens

Markup and styling kept; what each screen *shows* changes to match real data.
`src/app/platform/lib/data.ts` (1,654 lines) deleted wholesale — that deletion
is this phase's definition of done.

| Screen | Disposition |
|---|---|
| Portfolio | Wire to `clients` + latest run. Sort/owner become real query params — `state.picks` is currently written and read only by its own label. |
| Client overview | Real run history; "Compare runs" → `compareToBaseline` on two chosen runs. |
| Journeys | CRUD over `journeys`; step editor writes `JourneyStep[]`. "Record a journey" starts as a manual builder. |
| Findings | Filtering is already real; point it at the API. Mark-fixed/dismiss become `PATCH`. **Reshaped:** grouped by page, showing WCAG criterion and selector. The dismissal note is currently a `<span>` — a required field that can never be filled. |
| Reports | Persist `draftReport`; wire the existing PDF route. Share link → `share_token`; `/r/[token]` read-only and unauthenticated, so it needs `X-Robots-Tag: noindex` and rate limiting. |
| Activity | `activity_events` on every run/status/report action, attributed to the configured operator. |
| Settings | `ReadOnlyField` → real inputs writing `client_config`. **Dropped:** People, Invite, Integrations, logo upload — nothing backs them. |
| Header | Configured operator name, not the literal string "Jules Reyes". Fix the dead `#annotated-ledger` anchor. |

**Vocabulary:** one mapping function in `derive.ts` translating engine severity
and verdict to the prototype's display labels. Not a taxonomy rewrite — that
touches ~3,000 lines for zero behaviour change.

**Tests:** `platform-derive.test.ts` (276 lines) dies with `data.ts`. Replace
with tests over the mapping function and the query layer.

## Security decisions this phase forces

- `/r/[token]` is unauthenticated by design: high-entropy revocable token,
  `X-Robots-Tag: noindex`, rate limited.
- Artifacts currently upload with `access: 'public'` — an unguessable URL, not
  access control. Decide explicitly whether that is acceptable for client
  screenshots or whether they move behind a signed, authenticated route.
- `htmlSnippet` is untrusted markup and must stay text-escaped in the UI as it
  already is in the PDF. Never `dangerouslySetInnerHTML`.
